# Spec — Compress Rung 3: MRC for text-dominant colour scans

**LCW:** `20260723-mrc-rung3` · **Branch:** `feat/mrc-rung3` · **Status:** draft, pre-gate
**Prior specs:** `.claude/specs/20260722-pdf-toolbox-v1.md` (§ Rungs, R2-N1 routing fallback,
R1-M13 ship-without-Rung-3), whose Rung-3 spike precondition this LCW discharges.

---

## 1. Origin

The v1 spec staged MRC (mixed-raster-content) compression as Rung 3, gated on an empirical
segmentation spike (v1 spec risk #1: "segmentation quality is empirical"). v1 shipped without it.
The user asked to close the gap: colour scans — the document class where Rung 1 gains least —
are the bulk of their real workload, and the spike has now produced a verdict.

The problem MRC solves: a colour scan is one big JPEG per page to Ghostscript, so Rung 1 can only
downsample and re-encode it whole. MRC splits each page into a 1-bit text mask (compresses tiny,
keeps text razor-sharp), plus heavily-compressed low-frequency foreground/background colour
layers. Text-dominant scans shrink several-fold at equal reading quality; image-dominant pages
(continuous-tone full-page image content) are actively harmed — the background *is* the content there.

## 2. Verification evidence

All measurements on the maintainer's local 12-document colour-scan corpus (aggregates only —
the corpus itself must never be identifiable from this repo; see the `no-personal-corpus-references`
gate) plus the prior spike's synthetic corpus.

- **Reference-implementation spike (2026-07-23, this LCW):** `recode_pdf` (archive-pdf-tools)
  with v1-representable codecs (CCITT G4 mask, JPEG layers — no JPEG 2000, no JBIG2) on all 12
  documents. Every output validated (opens, page count, renders).
- **Tuned-baseline re-measure (same day, after brainstorm review):** Ghostscript re-run with the
  v1-spec-intended tuning (`AutoFilterColorImages/GrayImages=false`, explicit `QFactor 1.5`).
  MRC margin vs the **better** of {input, as-coded gs, tuned gs}: **min 1.66×, median 1.80×,
  max 3.42×** — every file clears the prior spike's pre-registered ≥30 % bar
  (`.git/lcw/20260722-pdf-toolbox-v1/mrc-spike.md` §0.3, machine-local). The as-coded-baseline
  headline (median 2.60×) is recorded as inflated and is not load-bearing.
- **Quality:** user-judged acceptable on the text-dominant class (faint, low-contrast colour
  marks survive), and **unacceptable on the image-dominant class** (a document whose pages are
  continuous-tone full-page image content; fine detail smeared). Judged via the reference tool.
- **Classifier separation:** ink connected-component statistics separate the classes at document
  level (indicative ~3× mean component size) but **fail at page level** — a large majority of the image-dominant document's pages passed a component-size-only threshold. Consequence baked into the design: the
  classifier is a cost-saver; the post-encode verifier is the correctness gate.
- **Mixed eligibility is real:** 4 of 12 corpus documents contain both eligible and ineligible
  pages under the candidate threshold → per-page handling retained.
- **Metric lesson (prior spike, pre-registered method):** global whole-page similarity is
  dominated by blank paper and stays high while text degrades; the corroborating signal was
  text-region similarity restricted to a dilation of the mask. R4 operationalises this.
- **Apple-renderer lessons (spike, empirical):** CoreGraphics silently renders ghost text when an
  MRC soft mask's ColorSpace is not `/DeviceGray` (ICCBased is rejected without error), and
  `recode_pdf` drops page `/Rotate` (every corpus file except one carries 90/180/270). Both are
  binding output invariants (§7). MuPDF renders both defects "correctly", so cross-viewer
  verification must include the CoreGraphics path.
- **Port-risk evidence:** the reference segmenter uses Sauvola binarisation, TV-Bregman denoising,
  noise estimation and custom fg/bg spreading — none with drop-in Apple-framework equivalents.
  Hence the port-fidelity milestone (§11): the spike proved the approach, not the port.

## 3. Decisions

Each with the user's why; rejected alternatives in one line.

- **D1 — Build Rung 3 at the honest margin (GO).** 40–45 % smaller than *tuned* Rung 1, every
  corpus file above the pre-registered bar; on the user's real batches that is megabytes per run.
  *Rejected:* park it (loses the majority-class win); JBIG2/native encoders (already rejected,
  DECISIONS 2026-07-23 — no native libraries).
- **D2 — Automatic engagement + visible tag + instant reversal** ("the redo button makes automatic
  safe, and users get the big win without knowing MRC exists"). *Rejected:* opt-in toggle (most
  users never find it); ask-per-document (noisy).
- **D3 — Presets: Balanced and Smallest only.** `maximumQuality` promises fidelity; MRC is a
  fidelity trade. *Rejected:* all-preset MRC.
- **D4 — Accuracy = cheap per-page classifier + per-page post-encode visual verification.**
  The verifier measures actual damage (the image-dominant class *provably* slips the classifier);
  the classifier only avoids wasted encodes. *Rejected:* classifier-only (unsafe), verify-only
  (wasteful).
- **D5 — Hybrid per-page composition.** gs runs whole-document regardless; MRC replaces the
  pages that pass classify+verify; declined/failed pages are re-rendered and JPEG-encoded by
  MRC's own raster path at the preset's target DPI. *Rejected:* whole-doc all-or-nothing (loses
  4/12 mixed docs); extracting images from gs output (a new PDF-parsing subsystem + transitive
  colourspace copying, rejected in the brainstorm review).
- **D6 — Verify before compose.** A failing page must be swapped before assembly; reverting after
  composition would need the exact splice machinery D5 rejects.
- **D7 — Ship the hybrid only if smaller than the plain gs output**, else ship the gs output.
  Makes "never loses to Rung 1" literally true at document level. The existing never-larger-than-
  input net stays underneath.
- **D8 — UI: "Heavy compression ⌄" capsule → popover → instant switch.** Both versions already
  exist (gs ran anyway), so switching is instant and reversible; the popover shows real first-page
  thumbnails and real sizes for both, thumbnail click opens Quick Look on that actual file
  (arrow keys flip versions). Mock-ups rendered from the repo's real DesignSystem components,
  user-approved. *Rejected:* second-line redo link (breaks row height); hover-swap tag label
  (poor affordance, user-rejected); X-icon (glyph collision with queued-row remove);
  in-app synced A/B comparator (a subsystem Quick Look already covers).
- **D9 — Task 0: tune Rung 1's gs flags** (`AutoFilter*=false`, per-preset calibrated `QFactor`)
  before any MRC work. Free ~30–40 % win for every document; keeps every later margin honest.
  QFactor values are calibrated in Task 0 (1.5 was the measurement stand-in, not the decision).
  The v1 baseline's third element, DCTDecode passthrough, is deliberately **out** of Task 0: the
  measured B2 baseline did not include it, and passthrough interacts with downsampling in ways
  needing their own measurement — it remains a recorded v1-spec intention, revisited separately.
- **D10 — Rung-3-internal failures are silent.** Any classifier/encode/verify/compose failure
  degrades to the gs result — a valid shipped compression, not a failure the user can act on;
  only actionable failure classes (encrypted, corrupt, gs failure) are user-visible.

## 4. Requirements

**Functional**
- R1. Documents classified `.scanColour`, on Balanced/Smallest, attempt Rung 3; all other
  classifications and presets are untouched.
- R2. Only simple single-image scan pages are eligible; any complex page (text layer, vector
  content, multiple images) sends the whole document down the plain gs path — the R5 fallback
  rasterises, which would destroy selectable text or vector content, while gs handles complex
  pages properly; one complex page therefore disqualifies the document rather than risking a
  rasterised page in the output.
- R3. Per-page decision: two-signal classifier (ink connected-component statistics + colour
  coverage), conservative thresholds; any doubt → page declined.
- R4. Post-encode, pre-compose verification per MRC page: render the candidate page and the input
  page at the same DPI and compare visual similarity **relative to the input page** (self-calibrating; no absolute
  floor), with the comparison **weighted to ink/mask-dilated regions — never a whole-page
  average**: blank background dominates a whole-page score, which stays high while text turns
  to mush (the prior spike's pinned method records exactly this trap). Failing pages take the
  fallback path.
- R5. Declined/failed pages: rendered at the preset's colour DPI and JPEG-encoded via ImageIO —
  the same raster/encode machinery as the MRC background layer.
- R6. Document gate: composed hybrid ships only if byte-smaller than the plain gs output;
  otherwise the gs output ships. Never-larger-than-input, OutputValidator, atomic rename, and
  original-untouched all apply unchanged on whichever ships.
- R7. When any page was MRC-encoded in the shipped output, retain the losing version and offer
  the switch (R8–R11). When none was, behave exactly as today.
- R8. Result row: neutral "Heavy compression ⌄" capsule beside the savings pill; single-line row
  height; non-MRC rows unchanged.
- R9. Capsule click → popover: one-sentence explanation, both versions side by side with real
  first-page thumbnails and real on-disk sizes/savings, current version marked, one switch button.
- R10. Switch: instant atomic swap on disk, reversible while the row remains; the row's size badge
  and capsule state update; no progress state (nothing is recomputed). If the runner-up file has
  vanished, the button honestly re-runs the job through the normal path (progress state returns), and on
  completion the originally requested switch is applied automatically.
- R11. Thumbnail click → Quick Look on that version's actual file; both versions are supplied
  to the panel so the arrow keys flip between them.
- R12. OCR interplay: OCR must accept Rung-3 output like any other PDF the app produced
  (incremental update appends to it; the verbatim-prefix invariant applies to the *new* file).

**Non-functional**
- R13. Memory: MRC holds per-page encoded payloads until compose (mask + fg + bg ≈ 3× Rung 2's
  footprint) → dedicated page cap (Task-calibrated, ≤ `maxBilevelPages`/3 order), per-page
  raster release, `maxBilevelPixels`-equivalent render bound, existing queue concurrency.
- R14. Classifier cost ≤ tens of ms/page (one ≈100 DPI RGB render, both signals from that one
  buffer); it must not visibly slow
  batches of ineligible documents.
- R15. Runner-up lifecycle: losing versions live in an app-managed cache directory, owned by the
  Compress view-model; deleted when the row leaves the list, the batch is cleared, or the app
  quits; stale entries swept at launch. This is a deliberate, documented exception to the
  "no persisted app state" invariant, bounded to crash-leftover sweep.
- R16. All Rung-3 work runs on the cooperative pool per the existing job-body rule (suspend on
  blocking work; never block a pool thread).

**Implementation constraints (from `.claude/memory/review-lessons.md`, binding)**
- C1. Never walk a CGImage buffer flat — address rows via `bytesPerRow`, sample only real `width`
  (classifier and verifier both measure ink/coverage; padding pollutes exactly these metrics).
- C2. Calibrate thresholds only after the underlying measurement is proven correct (C1 first,
  then calibration; thresholds tuned on a polluted metric encode the pollution).
- C3. Content-loss checks are relative to the same input page, never an absolute floor.
- C4. Batch output names allocated up front, serially (already the app's pattern — Rung 3 must
  route runner-up files through the same allocator, including the `-compressed` collision rules).
- C5. The shared-layer/parallel-fork ordering lesson binds the *plan*: every module both tracks
  need ships in the serial foundation phase.
- C6. This spec and everything committed must never identify the maintainer's machine or private
  corpus in any form (gate: `no-personal-corpus-references`, applied by intent).

## 5. Architecture

New module directory `Sources/Toolbox/Compress/MRC/`:

- **`MRCClassifier`** — per-page eligibility: renders ≈100 DPI RGB once (C1-compliant buffer
  walk); ink connected-component statistics on the luminance plane, coverage on chroma; returns per-page verdicts
  with the measured features, retained on the job result for tests and debugging.
- **`MRCSegmenter`** — the port: binarisation (Sauvola-class local threshold), mask cleanup,
  fg/bg layer construction with spreading/inpainting; pure functions over row-addressed buffers.
- **`MRCPageEncoder`** — mask → CCITT G4 via the existing Rung-2 `CCITTEncoder`; fg/bg → ImageIO
  JPEG at layer-specific downsample factors; per-preset parameters.
- **`MRCVerifier`** — decoded-layer recomposition rendered vs input page at equal DPI;
  ink-region-weighted similarity relative to input (R4, C3); returns pass/fail + score.
- **`MRCComposer`** — extends the existing single-image-page composition pattern
  (`BilevelPDFComposer` family) to emit per page either {bg image + fg image with `/SMask`
  (ColorSpace `/DeviceGray`) + CCITT mask} or {single JPEG image page}; carries `/Rotate`
  verbatim; streams pages, bounded memory.
- **`CompressEngine`** — orchestration only: routing (R1/R2), the gs whole-doc pass (existing
  runner, unchanged), per-page pipeline fan-in, D6 ordering, D7 document gate, runner-up handoff.
  Job closures keep the existing progress + error channels (per-page progress reported).
- **View-model/UI** — capsule + popover + switch (R8–R11) in the Compress tool; runner-up cache
  ownership (R15); FileRow gains one presentational state for "done with alternate available".

Explicit non-goals: no gs-output parsing, no JBIG2, no JPEG 2000, no per-page routing of
born-digital/mixed documents (v1.1 boundary unchanged), no custom A/B viewer, no OCR changes.

## 6. Error handling

- Any Rung-3-internal error (classifier, segmenter, encoder, verifier, composer) → that page
  falls back (R5) or, if composition itself fails, the document ships as the gs output (D10). Failures are silently
  swallowed — the app has no logging facility and adding one is out of scope; the per-page
  classifier/verifier verdicts retained on the job result (§5) are the debugging record.
- gs failure, encrypted, corrupt: exactly today's behaviour.
- Switch with missing runner-up: honest re-run (R10). Switch with missing *original* is
  irrelevant — the switch swaps two outputs the app owns.
- Cancellation: existing semantics — no partial output, staged work discarded, runner-up cache
  entry for a cancelled job removed.

## 7. Output invariants (byte-level, tested)

- I1. Every soft mask's ColorSpace is `/DeviceGray`.
- I2. Every output page's `/Rotate` equals its input page's.
- I3. Mask dimensions equal the mask's encoded dimensions; fg/bg dimensions consistent with their
  downsample factors; page MediaBox preserved.
- I4. The shipped file re-validates via the existing OutputValidator (open, page count, sample
  renders) — necessary but insufficient (it cannot see ghost text), hence I1/I2 are asserted
  structurally, and R4 verifies visually per page at encode time.

## 8. Performance

Per MRC document: 1 gs pass + 1 classifier render/page (~100 DPI) + 1 full-res render/page
(segmenter input) + 1 verify render/page + encodes. The reference tool ran on the order of a second per page in Python (indicative); the Swift
port must stay in that order. No caching/queuing/async machinery beyond the existing
queue (overengineering guard).

## 9. Testing

Synthetic, in-process fixtures only (existing fixture pattern; never corpus material, C6):

- Classifier: generated text-scan-like page passes, generated photographic/artwork page fails —
  including a page-level fixture pair reproducing "image-dominant page inside a text document".
- Smear regression: a committed synthetic image-dominant fixture that the *verifier* fails on
  when force-MRC'd — the CI stand-in for the image-dominant class, whose page-level classifier miss §2 records.
- Segmenter: mask correctness on known glyph shapes; no dropped thin strokes at 300 DPI-class
  input; C1 padding regression (odd-width buffers).
- Invariants I1–I3 asserted by parsing composed output bytes; I2 across 90/180/270.
- Verify-before-compose: a deliberately mangled page encode must ship as its fallback JPEG page.
- D7 gate: hybrid ≥ gs output → gs output ships.
- Switch: atomic, reversible, badge/capsule state, missing-runner-up re-run, lifecycle sweep.
- End-to-end: mixed synthetic doc (eligible + ineligible pages) → hybrid with both page kinds,
  validates, smaller than gs alone (when it isn't, gate fires).
- End-to-end OCR interplay (R12): OCR incremental update over a composed hybrid output
  validates; the hybrid file is the verbatim prefix of the OCR output.
- Task 0: preset argument snapshot tests updated; estimator error bound re-checked against the
  ±25 % criterion (v1 spec R1-M7) since output sizes change.
- Full existing suite + all `.claude/GATES.md` gates green; packaged-app smoke unchanged.

## 10. Risks & fallbacks

1. **Port fidelity** (top): Swift segmenter may not reproduce reference quality/sizes. Gate: M2
   milestone re-measures on the same local corpus; if quality or ≥30 %-bar fails → stop, ship
   Task 0 only, record in DECISIONS (the v1 "ship without Rung 3" posture remains valid).
2. **Verifier threshold calibration**: tuned on machine-local corpus, CI sees only synthetic
   proxies. Mitigation: conservative threshold + synthetic smear fixture + capsule/switch UI as
   the human backstop.
3. **Task 0 quality regression**: aggressive QFactor may visibly degrade Balanced. Mitigation:
   calibrate per preset against quality inspection before fixing values; snapshot tests.
4. **Memory on very long scans**: R13 cap; beyond cap → plain gs path (same shape as Rung 2's
   `maxBilevelPages` guard).
5. **Runner-up disk pressure**: bounded by batch size and lifecycle sweep; if a device is truly
   full the switch degrades to re-run (R10).

## 11. Milestones

- **M0 — Task 0**: tuned gs flags + QFactor calibration + test updates. Ships value alone.
- **M1 — Foundation (serial, shared)**: `MRC/` module skeleton, classifier (C1-correct buffers),
  composer extensions incl. I1/I2, verifier, fixtures. Everything both later tracks touch.
- **M2 — Port-fidelity gate**: segmenter + encoder complete; re-measure quality + sizes on the
  local corpus vs the reference-tool outputs; proceed only on pass (risk 1).
- **M3 — Engine integration**: routing, hybrid pipeline, D6/D7 gates, runner-up handoff, e2e tests.
- **M4 — UI**: capsule, popover, Quick Look, switch, lifecycle.
- **M5 — Gates + review team**: full suite, `.claude/GATES.md`, packaged smoke, LCW step-6 gate.

## 12. Definition of done

Task 0 shipped; on the maintainer's corpus the Swift pipeline reproduces the reference verdict
(every text-dominant file ≥30 % smaller than tuned Rung 1 at user-accepted quality); the
image-dominant document ships without visible degradation (verifier or classifier excludes it);
all §7 invariants hold byte-level; all §9 tests and every repo gate green; UI matches R8–R11 in light + dark; OCR accepts Rung-3 output; nothing in the branch identifies
the private corpus.
